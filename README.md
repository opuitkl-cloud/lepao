# 武汉理工校园跑
# WHUT绘跑

> GPS 轨迹绘制 + 武汉理工大学智慧体育自动提交工具

在地图上绘制跑步轨迹，一键提交到 WHUT 智慧体育系统。可以每天手动交，也可以在手机上常驻一个进程无人值守自动交。

---

## 功能

- **轨迹绘制** — 选择校园地图，用鼠标/触屏绘制跑步路线
- **打卡点管理** — 自动加载校区标准打卡点，点击切换激活/取消
- **一键提交** — 账号密码登录 → 验证 → beforeRun → OSS 上传 → stopRun 全自动
- **预设轨迹** — 画好的轨迹可导出成预设，之后不必重画
- **无人值守** — `auto.js` 常驻，每天在指定时段内随机时刻挑一条预设自动提交
- **登录过期检测** — 提交前自动检查 token 有效性，过期自动退回登录页
- **移动端适配** — 双页面布局

## 依赖环境

| 项目 | 要求 |
|------|------|
| **Node.js** | **≥ 18.14，用 20 LTS 或更高最稳妥** |
| npm 依赖 | **只有 `crypto-js` 一个**（`npm install` 装好即可） |
| 外部命令 | `openssl`，**可选** —— 仅在 `data/cert.pem` / `key.pem` 缺失时用来生成 HTTPS 自签证书。这两个文件已在仓库里，所以正常情况下用不到 |
| Python | **不需要**（早期版本的 `token.py` 已移除，登录逻辑全部在 `server.js` 里） |

**为什么卡在 18.14：** 登录要靠 `res.headers.getSetCookie()` 收 `Set-Cookie`，这个方法随 undici 5.19 进入 Node，**18.14.1 起才有**。低于它的版本登录会失败，而且报错信息具有误导性（会显示登录页里写死的那句「请输入正确信息」）。

不确定自己的版本行不行，跑一行就能验：

```bash
node -e "console.log(process.version, typeof Headers.prototype.getSetCookie)"
```

输出里是 `function` 就没问题。`fetch` / `FormData` / `Blob` / `AbortSignal.timeout` 等其余特性 18 就够。

服务端除了 `crypto-js` 只用 Node 内置模块：`http` `https` `fs` `path` `os` `zlib` `crypto` `child_process`。没有 Express，没有构建步骤。

## 快速开始

### Windows

双击 **`start.bat`**。它会检查 Node、首次运行自动装依赖、起服务、3 秒后打开浏览器。**关掉那个黑窗口就是停止服务。**

手动启动：

```bash
npm install
node server.js
```

然后访问 **http://localhost:6660**

### 手机 / Linux（Termux）

```bash
pkg install nodejs
npm install
node server.js      # 网页版；浏览器访问 http://localhost:6660
node auto.js        # 无人值守版；见下面的「自动提交」
```

两个进程互相独立，跑哪个都行：`auto.js` 不监听任何端口，`server.js` 把 `server.js` 当库注入函数（不是 HTTP 调用）。只在手机上做自动提交的话，**只跑 `auto.js` 就够**，而且不对外开放任何端口。

## 使用说明

1. **登录** — 用统一身份认证（zhlgd）的**用户名和密码**登录。注意是用户名，**不一定是学号**。
   若该方式不可用，展开"或用链接登录"：打开"智慧体育" → 右上角 → 浏览器打开 → 复制链接，粘贴进去
2. **选择地图** — 点击南湖/鉴湖/西院/余区/东院切换底图
3. **选打卡点** — 点击打卡点激活（粉色=已激活，青色=未激活）
4. **画轨迹** — 点击"开始绘制"在地图上画线，再次点击结束
5. **提交** — 点击 ⚡确认，自动检查登录 → 生成轨迹 → 提交到 WHUT

## 自动提交（Termux 常驻）

每天在指定时段内随机挑一个时刻，从预设里随机选一条自动提交，不用任何交互。

### 1. 先做出预设

在网页上画好一条轨迹、选好打卡点，点运动参数区的 **「⬇ 导出为预设」** 起个名字。每个校区、每条路线各导一次，文件存到 `data/presets/`，里面只有 GPS 坐标、打卡点和时长，不含凭据。

**导出前先点一次 ⚡确认**，看打卡状态栏是不是全绿 —— 轨迹必须经过打卡点 **200 米以内**，否则提交了也拿不到打卡记录。导出这一步不做这个校验，提交时才校验。

### 2. 填账号配置
创建文件
`data/auto.json`：

```json
{
  "username": "你的统一身份认证用户名",
  "password": "你的密码",
  "startHour": 9,
  "endHour": 18
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `username` | 是 | 统一身份认证用户名|
| `password` | 是 | 密码 |
| `startHour` | 否 | 默认 `9`。支持小数，`14.5` = 14:30 |
| `endHour` | 否 | 默认 `18` |

**这个文件里是明文密码**（无人值守没法每次手输），已加进 `.gitignore`。

### 3. 跑起来

```bash
termux-wake-lock            # 防止系统休眠时杀掉进程
node auto.js
```

先用 `node auto.js --once` 验证账密和预设是否可用。⚠️ **两个注意点：**

1. **它不是演练** —— 会真的提交一次、在智慧体育上生成一条跑步记录。
2. **它会把当天标记为「已提交」** —— 之后再启动 `auto.js` 常驻，今天就不会再交了（这是防重复提交的设计）。如果 `--once` 之后想让当天也自动交，就把 `data/auto-state.json` 里的 `lastSubmitDate` 删掉，或者直接跳过 `--once` 开始常驻。

### 行为说明

- 每 60 秒检查一次，**不是**睡一整天 —— 手机休眠唤醒、系统改时间、进程重启都能自愈
- 提交前**重新登录**，所以 token 过期不影响（每天一次登录，约 1 秒）
- 「今天已提交」记在 `data/auto-state.json`，**重启不会重复提交**
- 失败 10 分钟后重试，连续失败 5 次才放弃当天
- 随时往 `data/presets/` 增删预设文件都行，下一轮自动生效，**不用重启**
- 日志同时打到屏幕和 `data/auto.log`（只记账号和结果，**不记密码**）
- `Ctrl+C` 停止

## 常见问题

**登录报「请输入正确信息」**
这句文案**写死在登录页模板里**，任何被拒的登录都会显示它，不代表具体原因。99% 是**账密填错了** 

**电脑上能登录，手机上同样的账密失败**
多半是 `data/auto.json` 里混进了空格或换行。网页表单会自动去掉首尾空白，而这个配置文件不会。检查一下 `username` / `password` 的值。

**提交成功但记录无效 / 打卡是空的**
轨迹没经过打卡点。打卡点必须落在轨迹 **200 米以内**，且至少 2 个。在网页上先点一次 ⚡确认，看状态栏是否全绿。

**手机上打不开 https://IP:6661**
预期之内。那张自签证书没有 SAN，现代浏览器只认 SAN，会直接判证书无效。手机端请用 `http://localhost:6660`（在手机上跑服务端）或明文 HTTP。

**一天提交多次，后来的显示「当天关联成绩次数已达到上限」**
智慧体育对计分跑有每日次数限制。`auto.js` 默认一天只交一次，就是为了避开这个。

## 安全说明

**网页登录：** 密码只在服务端内存里用于换取 token，不落盘、不写日志，`localStorage` 里只存 token。

**自动提交：** 密码必须以**明文**存在 `data/auto.json`，这是无人值守的固有代价。该文件已在 `.gitignore` 里，但手机本身被翻到就是明文。

**网络：** 服务端默认监听明文 HTTP（6660）。电脑本机访问没问题（不出网卡）；用手机经局域网访问时，密码会明文过一次网络。

**6661 的 HTTPS 不能解决这个问题。** 自签证书没有 SAN，手机上大概率被判无效；更关键的是 HTTPS 解决的是"加密"，自签证书解决不了"认证"——被动嗅探防得住，主动中间人防不住。

手机端真正安全的做法是让服务端和浏览器同机：手机上用 Termux 跑 `node server.js`，访问 `http://localhost:6660`，密码不出设备。

## API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/whut/login-pass` | POST | 用户名密码登录，走统一身份认证换 token，返回 auth |
| `/api/whut/login` | POST | 用智慧体育链接登录，返回 auth（备用方式） |
| `/api/whut/check-auth` | POST | 检查登录是否过期 |
| `/api/whut/submit` | POST | 创建跑步任务，返回 jobId |
| `/api/whut/job/:id` | GET | 轮询任务状态 |
| `/api/whut/history` | GET | 历史记录 |
| `/api/settings` | GET/POST | 图层配置持久化 |
| `/api/presets` | GET/POST | 预设轨迹的列出与保存 |

## 技术栈

**后端：** 纯 Node.js 内置 `http` 模块，无 Express，无构建步骤
- AES-128-CBC 加密（crypto-js）
- MD5 参数签名
- RSA/PKCS1v1.5 加密账密换 CAS 票据（Node 原生 `crypto`）
- OSS 阿里云 STS 上传

**前端：** 纯 HTML/CSS/JS SPA，无框架
- Canvas 绘图
- GPS ↔ 像素坐标双向转换
- Haversine 距离计算
